# 05 复盘

## 1 用时与完成度

从读题到两通道全量通过，投入约 55 分钟，含实现、调试、接真实模型与文档；人工复核不计在内。

已完成：六个必验点全覆盖（11 组用例）、决策循环与双预算、冲突判定与三级消解、引用可核验、双通道各 11/11、数据驱动验证、五篇文档。

未完成（详见 `docs/03-evaluation.md` §7）：冲突召回保守，只认同主题同 key；消解只覆盖三种情形，且是整份文档粒度；没有 session，多轮靠外部传 history；`needs_clarification` 定义了没用上；真实模型跑过多轮但没做稳定性统计。

## 2 最难的问题

### 2.1 冲突的难点在假阳性，不在检测

检测本身不难：同一主题、同一个 key、不同取值，三条一比就出来了。难的是不该报的别报。

误报有两个来源。一个是跨主题的通用 key：D01 和 D07 都有「起算时点」，一个写出差结束、一个写加班发生，key 相同值不同就被判成冲突；这个假冲突又能被 D08 的取代声明消解，消解结果直接变成答案。另一个是弱相关文档：问住宿标准时，检索把 D01、D02 一起带回，这两份之间的真冲突污染了住宿问题。

对应的两条限定是分数窗口（≥ 最高分 × 0.5）和主题聚焦，细节在 `docs/02-solution.md` §3.2。

这里取宁漏不误。漏报的表现是两份文档各自作答，用户自己能发现不一致；误报会给出一个不存在的矛盾，比不答更糟。

### 2.2 引用校验会误杀

规则写严了会杀掉正确答案。按「答案里每个数字都要能在引用里找到」这条走，D08 标题里的「2026 年修订」会被判成无支撑数字，一条正确回答被降级成 `insufficient`。

太松则放过编造。处理办法是给指称形态开豁免（`第 3.1 条`、`v1.2`、`2026-06-01`、`D08`），并把被引文档的标题、版本、生效日期算进可核验范围，它们本来就是同一份文档的元数据。

由此定了一条规矩：护栏每加一条规则，配一个反例测试。`test_clause_reference_numbers_are_exempt` 就是这条规矩的产物。不配的话，护栏自己会变成新的缺陷来源。

### 2.3 模型判断和代码判断的分界

「哪份制度更权威」如果交给模型，会有三个问题：结论不可审计、换文档内容后行为不可预测、审核要点恰好要验这一点。

分界最后定成：模型选动作、写叙述；代码判事实、判引用、判预算。划清之后，规则策略和真实模型能共用同一个 Action 契约，trace 格式也不用分叉。

### 2.4 真实模型会严格照证据格式引用

规则策略按模板产引用，天然对得上原文；模型不是，它会照提示词里的证据格式产引用。

把多行片段用 `" / "` 拼成一行喂进去，模型就照着这个格式拼 quote，11 组挂了 7 组，理由全是「引用原文找不到」。再加上行首 `- ` 复制时丢掉、提示词里没有当前日期这两处，一共四个缺陷，全在实现层，与模型能力无关。

处理方式是两边一起改：证据逐行渲染、归一化去掉列表符号、状态里加当前日期，同时判定层补 `_is_effective()`，未生效的修订版不能拿来消解冲突。只改提示词，换个模型还会犯；只改判定层，模型会继续给出和判定结论相反的叙述。

结论是：规则策略跑通不等于系统可用。它只能证明一条路径成立，接口层的假设要等第二个实现接进来才会暴露。

## 3 学习收获

1. Agent 的可解释性在 trace 的字段设计里，不在提示词里。每步记动作、参数、依据、观察结果，评审不看模型内部过程也能判断决策合不合理。`reason` 一句话就够，但不能没有。
2. 测试要测「不该发生的事」。11 组用例里有 3 组断言某个内容必须不出现：C2 不能只给一个数值，C3 不能编比例，C9 不能给答案。这类反例比「能答对」更容易暴露设计问题。
3. 数据驱动测试最有说服力。改 markdown 里一个数字，结论跟着变，比写一段话解释「没有写死」有力。
4. 零依赖不是洁癖，是交付可靠性。评审在一台没配环境的机器上能一条命令跑通，比多一个框架的抽象能力重要。

## 4 下一步

按值不值排。

1. 真实模型的稳定性测试，半天。同一条用例跑五到十次，统计状态分布与路径差异。「八次答对、一次追问、一次拒答」这种数字才能拿去和业务方谈。
2. `supersedes` 做到条款级，一天。现在是整份文档取代，模型的读法却是按生效日期分段适用，两边在 C8 给了不同但都合理的答案（见 `docs/03-evaluation.md` §9.4）。要做对得让元数据支持 `D07#4.2`，答案里显式写出适用区间。
3. 冲突召回扩到「不同措辞」，一天。把 claim key 归一化（同义词加简单聚类），让「报销期限」和「报销时效」对齐。代价是误报率上升，得同步补一组负样本。
4. 引用粒度从整节细到句，半天。现在引用整节原文，核验偏松，节里任何数字都算支撑。句级绑定更紧，但要处理跨句指代。
5. 消解规则补两级，半天。「特别规定优于一般规定」「上位制度优先」。需要元数据里加 `level` 和 `specialty`，还得在数据里造出可验证的样例。
6. session 与多轮，一天。CLI 加会话文件，`history` 由系统维护，不再靠调用方传。
7. 用例扩到 50 条并分场景统计，一天。11 条够覆盖验收点，不够谈准确率。扩完应该报分场景通过率，不是笼统的「通过」。

## 5 最后

这道题的考点不是让模型答对，是在资料不可靠的时候，系统还愿不愿意说「我不知道」。冲突暴露、引用核验、预算上限，做的都是同一件事：把不确定变成显式的、能核对的状态，别藏在流畅的措辞里。
