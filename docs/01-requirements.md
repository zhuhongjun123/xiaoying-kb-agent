# 01 需求：用户、目标和成功标准

输入输出契约、状态机、动作空间这些实现层面的约定放在 `docs/02-solution.md` §2，这里只谈需求和标准。

## 1 场景

员工遇到制度或产品问题，路径通常是问 HR、等回复，或者自己去共享盘翻，翻到哪份算哪份。这三种麻烦决定了这个项目要做什么：

| 麻烦 | 具体表现 | 对系统的要求 |
| --- | --- | --- |
| 找不到 | 不知道该查哪份，关键词和标题对不上 | 检索要能吃口语，不能只认正式术语 |
| 找到但不一致 | D01 说 30 天、D02 说 15 天，两份都写着现行有效 | 暴露冲突，不替用户选 |
| 找到但不敢用 | 不知道有没有废止、是不是适用于自己 | 给出 doc_id、版本、生效日期、适用范围 |

第二类是我最在意的。员工按 15 天提交被驳回，或者按 30 天提交结果已经超期，责任最后落在系统头上。所以这个项目的重点不是答得多，是答得能核对，答不了就说答不了。

## 2 用户

主力用户是普通员工，问报销期限、设备借用、请假、产品导出规格。他们的场景是手上有件事要办，需要一句能照着做的答案，不是来浏览资料的。

另一类用户是制度维护者，HR、财务、行政。他们关心的是系统有没有把没意识到的矛盾翻出来，所以冲突必须出现在结果里，不能只写进日志。这条需求决定了冲突要作为一等输出，而不是异常分支。

不服务的：外部客户、跨租户、按角色做权限过滤。知识库默认全员可读。

## 3 目标

每条都对应到能跑的东西，写在文档里不算完。

| 编号 | 目标 | 怎么验 |
| --- | --- | --- |
| G1 | 回答带 `doc_id` 和原文片段，片段能在原文里字符串比对通过 | `guards.verify_answer` + `citation_check` |
| G2 | 同一主题同一事项出现多个取值时，全部列出并请求确认 | C2、C4 |
| G3 | 库里没有就明确拒答，不拿常识凑 | C3 |
| G4 | 换个问法，结论要和原问法一致 | C4 对照 C2 |
| G5 | 追问能继承上文的主题和文档焦点 | C5 |
| G6 | 工具失败不静默、不猜；能换策略就重试，不能就说明缺口 | C6、C7 |
| G7 | 有步数和工具调用上限，到顶返回明确的未完成态 | C9 |
| G8 | 换掉文档内容，答案和动作要跟着变 | `tests/test_agent.py::TestDataDriven` 的 7 条 |

## 4 范围

做：CLI；9 份合成制度与 FAQ；四个动作的决策循环；冲突判定与消解；引用核验；故障注入；11 组用例；双模型通道。

不做，理由是不在题目要求里，或者会超出三小时的预算：

- 界面、线上部署、多 Agent 编排、生产级 Runtime；
- 真实文档接入（PDF/Word 解析、OCR）。`data/docs/*.md` 就代表「已经结构化好的知识库」这一层；
- 权限与多租户；
- 任何写操作，比如提交报销单、改制度。

## 5 对着题目的六个必验点

题目列了六种必须覆盖的情况，我各配了用例，另加一组预算耗尽的边界。

| 必验点 | 用例 | 断言什么 |
| --- | --- | --- |
| 明确答案 | C1、C10、C11 | 状态 answered，引用命中预期文档，答案里有预期数值 |
| 文档冲突 | C2 | 状态 conflict，同时引用 D01 和 D02，两个数值都在答案里，带下一步 |
| 资料外问题 | C3 | 状态 out_of_scope，无引用，答案里不出现编造的比例 |
| 改写后的相似问题 | C4 | 状态和 C2 一致。换个问法不能变成单选题 |
| 上下文追问 | C5 | 「那续借呢」单看无法检索，必须靠 history 恢复主题 |
| 工具失败 | C6、C7 | C6 重试后成功；C7 连续失败后拒答，不猜 |
| 预算上限 | C9 | 状态 unfinished，不输出答案，说明已检索到什么 |

验证材料按规范覆盖三类场景：正常（C1、C10、C11）、信息或资料不足（C3、C7）、工具失败（C6、C7）。每条用例的输入、实际输出和运行记录分别在 `examples/inputs/`、`examples/outputs/`、`examples/transcripts/`。

## 6 成功标准

1. `python run.py run-cases --strict` 退出码 0，11 组断言全过；
2. `python -m unittest discover -s tests` 37 条全绿；
3. 所有 `answered` 和 `conflict` 结果的 `citation_check.ok` 为真；
4. 数据驱动测试能证明结论不是写死的：把 D01 的 30 天改成 45 天，答案跟着变；把 D02 也改成 30 天，冲突消失；
5. 克隆到新目录跑用例与测试后，`git status` 为空，产物可复现。
