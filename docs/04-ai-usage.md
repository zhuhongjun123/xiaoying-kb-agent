# 04 AI 使用说明

AI 用于起草代码、测试、用例和文档；方案的边界与判定口径由我确定，落地结果逐条复核。

## 1 使用范围

动手前定下五条边界，实现都在框内：

| 边界 | 内容 | 落到哪 |
| --- | --- | --- |
| 运行门槛 | 一条命令能跑，不装包、不要 key | 零第三方依赖，规则策略通道离线可用 |
| 模型 | 双通道：离线规则策略兜底，另留 OpenAI 兼容入口 | `policy.py` / `llm.py` 共用同一个 Action 契约 |
| 判定权 | 「谁更权威」「引用对不对」由代码判 | `guards.py` 的消解阶梯与引用校验 |
| 思路延续 | 与已有项目 `rs-research-copilot` 同一套骨架 | `docs/02-solution.md` §7 的对照表 |
| 记录 | 已知限制照实写，没验的标没验 | `docs/03-evaluation.md` §7、README「已知的问题」 |

AI 起草的部分：

| 环节 | 内容 | 位置 |
| --- | --- | --- |
| 用例 | 按六个必验点铺出 11 组，含故障注入与预算覆盖 | `data/cases.jsonl` |
| 合成知识库 | 9 份制度与 FAQ，带 doc_id、版本、生效日期、优先级、替代关系、主题 | `data/docs/` |
| 内核代码 | 决策循环、文档解析与 BM25、冲突消解、引用校验、CLI | `src/`，9 个文件 |
| 测试 | 37 条 unittest，其中 7 条是「改文档看结论是否变」 | `tests/`，3 个文件 |
| 运行记录 | 输入、输出、trace、transcript 各 11 份，真实模型一套同构的 | `examples/` |
| 文档 | README 与 5 篇 docs | `docs/` |

## 2 我调整的六处口径

| 调整项 | 最终做法 | 理由 |
| --- | --- | --- |
| 引用校验 | 字符串子串比对加数字绑定，对不上整条降级为 `insufficient` | 只由模型声明「引用了 D01」等于没验。错误引用在题目里属关键缺陷，须机器判定 |
| 冲突判定归属 | 移入 `guards.py`，用 claim 比对加三级消解 | 审核要点要验「换文档内容结论跟着变」，放在提示词里这一步不可测 |
| 预算 | 步数与工具调用次数双上限 | 一次检索会带出多次原文读取，单上限挡不住工具风暴 |
| 规则策略的定位 | trace 里如实标注 `provider=mock-rule-policy` | 题目要求标明 mock 边界，规则策略只作执行骨架 |
| 文档措辞 | 去掉「完整」「彻底」「全面」，改为具体做了什么、没做到什么 | 评审要判断的是能否核对，形容词不算证据 |
| 用例断言 | 补「必须不出现什么」：C2 不能只给一个数值，C3 不能编比例，C9 不能给答案 | 反例比正例更容易暴露设计问题 |
